## Actual behavior

The exported C `MCM_Describe` uses optional MCMv3 callback settings and v5
defaults. It registers exactly the existing20 player settings plus Detailed
log last, defaultOFF; no developer/benchmark dump. Original ranges, choice
values/words, custom modes, dependency text and13 startup flags are retained.
MCM supplies restart markers. The vendored unmodified `gui/ModConfigMenu.h`
is a portable snapshot of the current sharedv6 interface; it adds no MCM link
dependency. Runtime translation remains the current KeoTr boundary.

Callbacks keep static bounded module/key contexts, with each page's offered
choice mask retained for its lifetime (including a previously selected PROD
observe mode). Getters copy one2560-byte owned module stage; they do not read
INI, translate, query native options/world state or apply settings. Setter
contexts, types, finite floats and choice membership are checked. Calls off
the initialized main thread refuse safely without native localization.

Shared commit merges only edits relative to a frontend's opening baseline into
the latest requested snapshot. This prevents a stale native editor from
reverting newer MCM changes to other keys. Existing clamp/floor/custom-value
and flat writer functions are reused. Save completes before requested
publication and live apply; failure leaves both requested and running values
unchanged. Repeated unchanged setters do no file work. Unexpected post-save
apply exceptions report saved/not-applied-until-restart rather than rollback.
The existing writer's success logging is now exception-contained after atomic
replace, so a logging allocation failure cannot disguise a completed save.

Only changed live rows apply. Other modules use the original aligned field
stores through a one-row filtered table; render applies start from the running
render config and copy only changed live fields. Unrelated requested ON fields
cannot revive effective refusal/master-OFF fields. Startup settings never
reinitialize workers, hooks or caches. Fast-zone-hopping floor reads occur only
for an edited squad-radius value after runtime admission.

Platform admission and runtime admission are separate. Before/after a refused
build gate, page strings/errors use English without calling the native locale
manager; the page can still save requested settings. A validated platform can
translate even when partial hooks prohibit native live apply. Runtime apply
requires completion of the original hook/render install phases. Debug changes
only the plugin's own cached logging flag safely; Task3 must still gate real
diagnostic producers and synchronize localization summaries.

PROD probes the loaded MCM_OpenPage export at every Options-create call,
independent of discovery/hook order. Compatible MCM suppresses the duplicate
native player editor. Absent/older MCM keeps it; DEV retains the original
diagnostic/benchmark editor. Original create/save calls remain exactly once.
Stale staging is forgotten before every create, and both editors share the
requested snapshot/atomic commit. User settingsPanel preference is retained.
