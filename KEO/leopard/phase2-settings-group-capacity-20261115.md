# Fallback settings group capacity, 2026-11-15

Capacity-only stage change in `src/gui/settings_panel.cpp`; layout, settings, callbacks, native guards and localization are unchanged. The panel stored eight dependent lines, but its actual PROD table now contains sixteen: nine RAM-cache children plus seven routing/backpack/throw-out children. Later rows intentionally fell through enabled when storage filled.

The static array bound is now derived from the existing bounded staging capacity: `CONFIG_MODULE_MAX * CONFIG_STAGE_MAX` (10 * 128). It can hold every staged config row, so the current sixteen children fit without tying storage to the current table length. On x64 the 24-byte entry array grows from 192 to 30,720 bytes of process-lifetime static storage; no new allocation, per-frame scan, lifecycle reference or callback operation. The existing overflow fallback remains defensive.

`leopard/test_settings_gated_capacity.py` compiles the existing `tools/tests/settings_layout_units.cpp` actual-table fixture, injecting the actual production panel capacity declaration and a capacity assertion after its independently enumerated sixteen head/member checks. It also validates actual module/key counts against the existing staging bounds. This tests the real table and production capacity without pretending to instantiate MyGUI widgets. Old production compiled and failed one assertion at runtime. Final VC10 /Od and /O2 pass all existing layout checks plus capacity invariants; a compiled /O2 old-eight-capacity mutant fails the same assertion. Logs: `build/settings-gated-capacity`. No new GUI/game run, DLL build or installation.
