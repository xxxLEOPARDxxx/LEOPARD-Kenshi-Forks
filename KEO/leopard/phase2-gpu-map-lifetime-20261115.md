# GPU map-node lifetime guard, 2026-11-15

Stage-only correction after source audit; no new native hooks, game execution, full DLL build, installation or measurements.

`gpu_params.cpp` previously cached SDK/custom-owned map definitions even though actual SDK final release bypasses the watched native DAC30 destructor. `gpu_upload.cpp` also used only the actual deletion count to validate raw-definition plans: a same-pointer rebind after map erase/rebuild dropped lookup entries but left those plans matching.

Persistent lookup entries and upload plans now require the previously admitted native control-block vtable contract. The helper borrows the existing params SharedPtr fields without copying ownership, allocating, loading a module, or invoking a native function. Unknown/SDK/no-free control blocks forward through the native path and never add persistent node pointers. The existing setter fallback remains; its invalidation now advances a separate map revision before native forwarding. Actual watched deletion also advances that revision. `GpuNamedConstantsDeleted()` still counts only actual watched deletions; upload plans use `GpuNamedConstantsRevision()`. Public declarations are in `render_levers.h`.

Independent review caught an additional stale-buffer-copy path before integration: a native map A establishes a valid shadow, an already-created SDK map B uploads different bytes into the same GPU buffer, then A can appear identical against its old shadow. Unknown-map fallback now raises the existing copy-invalidation flag before forwarding to native, so a later tracked upload refreshes its copy. The new actual production-hook fixture alternates native A -> SDK B -> native A on the SAME buffer, simulating only the original GPU upload boundary. It compiled before this correction and failed two runtime assertions; no setter/deletion or map revision changes occur between those calls. A fourth identical native call still skips correctly.

No new per-frame scan, hook, cache, timer, thread or filesystem work. Native lookup admission adds only borrowed field loads and pointer comparisons; revision increments happen only at the existing invalidation seams. Unsupported map owners lose this optional optimization and keep native behavior.

Verification: new `leopard/test_gpu_map_lifetime.cpp` includes both actual production wrapper bodies, constructs real native Ogre params/programs/maps, and links production cache/plan/shadow primitives. The fixture's D3D buffer-layout scaffolding exercises the plan seam without creating a renderer or GPU. It first proves a stored definition is the actual map node, erases/rebuilds that real map, then poisons only the stored old pointer with PAGE_NOACCESS to make an otherwise allocator-dependent stale read deterministic. Production must rebuild before dereferencing it.
