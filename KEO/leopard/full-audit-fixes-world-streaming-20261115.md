# Private source audit: fixes/world, streaming and common helpers (2026-11-15)

All 64 assigned CPP/H files were read, including the detours, pure policies, storage and lifecycle contracts. The other 53 files in fixes/search, stitch and physx are independently covered by the navmesh auditor. Coverage is recorded in the adjacent JSON manifest. This is source/native-contract review and offline testing, not a game performance measurement or proof that every engine defect has been removed.

## Corrections

1. `world/corpse_pin.cpp`: after the native position call, the fix previously queried every member of every normal living squad before its policy immediately returned the native result. Collection now returns on the first living Character, exactly matching the existing policy's authoritative first pass. All-dead/carried squads still use the complete original policy and carrier ABI. No new table, clock, allocation, pointer retention or native call. `test_corpse_pin_live.py` extracts the actual detour and links the production policy. Old code failed the living-squad duplicate-query assertion; corrected VC10 /Od and /O2 each pass 21 controls, including carried corpse before a living member, all-dead/missing carrier, successful carrier output, disabled/null/empty/over-cap paths. Independent review passed.

2. `streaming/navmesh_life.cpp`: lifecycle diagnostics previously sampled native instances/meshes, updated counters and read the timer with detailed logging off. Only its log consumers use this state. Add sampling and the remove detour now bypass diagnostic work when detailed logging is off; the native removal still runs exactly once with its original arguments/result. `test_navmesh_life_idle.py` compiles the actual two production bodies with only native boundaries substituted. Baseline compiled and failed first; 9 controls pass /Od and /O2, including off/on/off and the disabled add flag. Error/crash recorders and functional section registration are unchanged. Mid-session enabling starts a partial diagnostic history; counts do not represent work while disabled.

3. `streaming/section_key_ring.cpp`: crash formatting previously walked tickets back toward session start while looking for enough published rows. If slots were unpublished, work scaled with the total session ticket rather than the 8 stored records. A per-site visited bound now stops after 8 tickets; output ordering and the existing maximum shown remain unchanged. `test_section_key_format_bound.py` extracts the actual formatter: old code failed a 100,000-ticket unpublished case; 9 controls pass /Od and /O2, including holes, newest-first output, zero limit and null/small buffers. Independent review passed. This DEV-only diagnostic remains best effort: no stable concurrent snapshot or counter-wrap correction is claimed.

## Boundaries and remaining findings

- `destroy_list_defer.cpp`: the 1024-entry deferral queue has a bounded 8x32 main-thread flush, deduplication and explicit world-clear dropping. Its native fallback on overflow is deliberately still racy; replacing that with dropping work would leak objects, and a full delivery redesign needs separate native ownership proof. The always-on invariant probe reports errors, so it was not disabled with diagnostic logs.
- `near_page.cpp` searches allocation-granularity candidates within a fixed rel32 radius. In a highly occupied address range it can issue many VirtualQuery calls, but no saved evidence attributes the user's startup delay to this helper. No unproven allocation rewrite was introduced. The successfully installed patch pages are intentional process-lifetime storage. A failed site-protection attempt in town_claim_patch can retain an unreferenced small allocation; that bounded exceptional startup path is not asserted to cause campaign FPS loss.
- `nest_validation` keeps its per-cell ledger/reset and native readiness check. Bounds guards in `mesh_face_guard` and `create_instance_guard` do real work even with logs off; they were retained. Per-face edge validation must not be removed merely because it duplicates a native walk: the native code does not validate those indices itself.
- Existing on-screen stagger applies only to far, previously off-screen eligible NPC checks, with player/engaged/gigantic/visibility exceptions and camera-jump/save-load refresh. Paused skipping still performs zone presence and periodic full refresh. Neither feature freezes world AI/pathfinding/physics. Their presence explains why off-camera loaded squads can still consume CPU.
- Throw-out holds and town-claim callbacks retain their bounded storage and existing native ordering. No unbounded campaign accumulation was established here. Ring/sequence wrap and best-effort diagnostic snapshot limitations are recorded rather than represented as fixed leaks.

No new hook, ABI offset, localization string, setting, gameplay timer or public release was added by these three corrections. Existing native addresses and the user's settings are preserved.
